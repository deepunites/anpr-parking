### ADR-10: Репозитории на SQLAlchemy Core `text()` + asyncpg, без ORM-моделей

**Контекст:** Схема принадлежит SQL-миграциям (фаза 2): партиционированные таблицы, RLS через `set_config`, `FOR UPDATE SKIP LOCKED`, `INSERT … ON CONFLICT … RETURNING`, enum-типы, триггеры. ORM-маппинг 37 таблиц стал бы вторым описанием схемы, которое дрейфует от миграций и плохо выражает партиции.

**Решение:** Репозитории в `modules/*/infrastructure` пишут SQL явно через `sqlalchemy.text()` на `AsyncSession` (asyncpg) и маппят строки в доменные объекты небольшими функциями. SQLAlchemy даёт пул, транзакции, `AsyncSession`, единый DSN; типы строк проверяются интеграционными тестами на реальном PostgreSQL, не декларациями. Именованные параметры `:name`, никакой конкатенации значений.

**Отвергнуто:**
- Декларативный ORM — двойное описание схемы, неявные `SELECT` при обращении к атрибутам, `expire_on_commit` и lazy-load на async ломают границы транзакций (I-9).
- Чистый asyncpg без SQLAlchemy — теряется общий пул/сессия, Alembic всё равно требует SQLAlchemy.

**Последствия:** проще — SQL совпадает с тем, что показывает `EXPLAIN`; дороже — маппинг вручную, ошибка в имени колонки ловится только тестом (поэтому у каждого репозитория есть интеграционный тест).

**Риск:** SQL-инъекция через форматирование строк — исключается правилом «только bind-параметры», проверяется ruff S608 и тестом фазы 8 на инъекции.
