### ADR-04: Кеш решений доступа в Redis с двойной инвалидацией; вступление в силу ≤ 5 с

**Контекст:** Каждый ENTRY и EXIT (до 400 RPS) запрашивает решение доступа. Попадание в blacklist обязано вступать в силу быстро и с предсказуемой верхней границей (I-8).

**Решение:** Redis-кеш `AccessDecision` по ключу `(tenant_id, lot_id, plate_hash)`, TTL 300 с; локальный кеш процесса, TTL 5 с. Любая запись правила кладёт `access.rule.changed.v1` в outbox в той же транзакции; после коммита post-commit hook немедленно удаляет ключи Redis для этого номера (все площадки tenant), а потребитель события удаляет их повторно и публикует pub/sub `access:invalidate` для локальных кешей. Заявленная задержка вступления в силу **N = 5 с** — TTL локального кеша. При недоступности Redis — прямой запрос в БД, не отказ.

**Отвергнуто:**
- Только TTL без инвалидации — blacklist вступает в силу до 300 с.
- Только локальный кеш процесса — не разделяется между репликами, инвалидация требует широковещания на все поды.

**Последствия:** проще — одна структура ключа, одна точка инвалидации; дороже — тест «прогретый кеш + добавление в blacklist → эффект ≤ 5 с» и сдвоенная логика инвалидации.

**Риск:** post-commit hook упал, а outbox отстаёт — окно до 300 с. Обнаруживается метрикой `outbox_publish_lag_seconds` (алерт > 5 с) и тестом инвалидации в CI.
