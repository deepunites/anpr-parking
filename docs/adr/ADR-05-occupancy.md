### ADR-05: Occupancy — счётчик в Redis как проекция; истина — активные сессии в PostgreSQL

**Контекст:** Занятость нужна операторам в реальном времени по 1 000 площадок; `ParkingSpot` не привязан к сессии — ANPR не знает, где встала машина; `COUNT(*)` на каждый запрос дашборда неприемлем.

**Решение:** Occupancy = число сессий в статусе `ACTIVE` по площадке. Потребитель `parking.session.created/closed/orphaned` инкрементирует и декрементирует `occ:{lot_id}` в Redis и публикует `OCCUPANCY` в WebSocket. Раз в 60 с джоб сверяет счётчик с `COUNT(*)` по partial-индексу активных сессий, перезаписывает при расхождении и пишет метрику `occupancy_drift`. `ParkingSpot.status` в occupancy не участвует — это справочник вместимости; при расхождении побеждают сессии.

**Отвергнуто:**
- Счётчик в агрегате `Lot` в БД — горячая строка на каждую сессию, конкуренция блокировок на пике.
- Материализованное представление — задержка refresh и пересчёт по сотням миллионов строк.

**Последствия:** проще — O(1) чтение, одно место эмиссии `OCCUPANCY`; дороже — сверочный джоб, метрика дрейфа, порог `deny_entry_when_full` вычисляется по проекции, а не по истине.

**Риск:** потеря Redis обнуляет счётчики — восстанавливаются сверкой за ≤ 60 с; систематический дрейф означает потерянное событие и виден в `occupancy_drift`.
