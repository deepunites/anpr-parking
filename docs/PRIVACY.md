# Персональные данные: ЗРУ-547 / GDPR — фаза 10 §3

**Статус:** 2026-09-20. Процесс запроса субъекта реализован и проверен тестом
[`tests/privacy/test_erasure.py`](../backend/tests/privacy/test_erasure.py) (полный цикл, необратимость, неизменность
финансовой отчётности). Код: `modules/privacy` (domain — состояния и SLA, application — шаги, infrastructure —
SQL + удаление всех версий объектов MinIO), API `/api/v1/privacy/requests*` (право `privacy:manage`, TENANT_ADMIN),
миграция `0014` (`deletion_request.vehicle_ids`, функция `app.anonymize_vehicles`).

Юрисдикция — Республика Узбекистан, ЗРУ-547 «О персональных данных» (CORE Q6), локализация — жёсткое требование;
GDPR-механики (право на удаление, минимизация, DPIA) применяются как надмножество. Номер ТС трактуется как ПДн.

## 1. Реестр обработки

| Данные | Где | Зачем | Основание | Хранение | Кому передаются |
|---|---|---|---|---|---|
| Номер ТС | `vehicle.plate_hash` (HMAC-SHA256 с ключом tenant), `vehicle.plate_encrypted`, `anpr_event.*`, `manual_correction.corrected_plate_encrypted` (AES-256-GCM, DEK tenant из Vault, I-10) | учёт въезда/выезда, расчёт и оплата парковки, льготы/чёрный список, споры | договор оператора парковки с владельцем ТС (публичная оферта на площадке); ст. 15 ЗРУ-547 (обработка для исполнения договора) — A-67 | `vehicle`/`parking_session` 7 лет (финансовый ретеншен), `anpr_event` 400 дней (A-18), `anpr_idempotency` 7 дней | никому: платёжные провайдеры получают `payment_id`, сумму и описание `Parking session <uuid>` (`billing/application/online.py:143`), не номер |
| Изображения кадров (номер и ТС в кадре) | MinIO `parking-media`, `media_object`, `anpr_event.image_object_key` | доказательство события при спорах, ручная коррекция номера | тот же договор; законный интерес — защита от мошенничества | 90 дней (MinIO lifecycle, фаза 4), `media_object` 4 мес | никому; presigned-ссылки ≤ 15 мин только операторам tenant |
| Контакт субъекта (телефон/e-mail при запросе на удаление) | `deletion_request.subject_contact_encrypted` (AES-256-GCM) | ответ субъекту по запросу | ст. 30 ЗРУ-547 (запрос субъекта) | до COMPLETED/REJECTED, затем `NULL` (`service.py::_step_complete`) | никому |
| Учётные данные операторов | `app_user` (e-mail, argon2id-хеш, роль), `refresh_token` (хеш), `login_attempt` (IP) | аутентификация и RBAC | трудовые/договорные отношения tenant с сотрудниками | пока активен; `login_attempt` 30 дней; refresh — до истечения | никому |
| Служебные следы действий (user_id, IP, User-Agent в `audit_log`) | `audit_log` | подотчётность ручных действий (I-15), расследования | законный интерес; требования к аудиту платежей | 5 лет (партиции дропаются) | никому |
| Телеметрия (логи, метрики, трассы, Sentry) | Loki/Prometheus/Tempo/Sentry — **все внутри контура** | эксплуатация | законный интерес | логи 30 дней, метрики 15 мес, трассы 7 дней | никому; ПДн в них не попадают (§2) |
| Данные сотрудников v2: телефон, отображаемое имя, признак временного пароля | `app_user.phone` (E.164), `app_user.display_name`, `must_change_password` | вход по телефону, приглашения, подписи ручных действий в отчётах | трудовые/договорные отношения tenant с сотрудниками | пока учётная запись существует | никому; в дашборде владельца — только имя сотрудника его же клиента |
| Приглашение сотрудника (e-mail/телефон, имя, роль) | `user_invite` (в БД — только sha256 токена) | выдача доступа по ссылке | то же | 48 ч ссылка, затем 30 дней после срока — удаление (`backend/scripts/retention.sql`) | ссылку администратор отправляет сам (мессенджер/SMS) |
| Заявка на регистрацию клиента (e-mail, телефон, название, код) | Redis `signup:*` | подтверждение владения контактом | согласие при регистрации (галочка, обязательна) | 15 минут, затем удаляется сама (TTL) | SMS/Telegram-шлюз — после его подключения (D-3) |
| Контакт клиента-юрлица (телефон администратора) | `tenant.contact_phone` | связь владельца платформы с клиентом (оплата, отключение) | договор с клиентом | пока клиент существует | владельцу платформы (сводка «Клиенты платформы»; данных водителей там нет, A-14) |
| Журнал событий камер (маска номера, время, камера, причина отказа) | `event_journal` | диагностика интеграции камер клиентом | законный интерес | 7 дней (партиции по дням) | разработчику/администратору клиента; открытого номера нет (CHECK в БД, I-10) |
| Исходящие вебхуки и журнал доставок | `webhook_delivery.payload`; адрес клиента | передача событий во внешнюю систему клиента | поручение клиента (он включает подписку) | 30 дней | в систему клиента по его адресу; **номера машин не передаются** — только идентификаторы сессий/платежей и суммы (A-90) |
| Тестовый приёмник вебхуков | Redis `inbox:*` | проверка интеграции без своего сервера | законный интерес | 24 ч, 20 последних запросов | никому; содержимое — только своему клиенту |
| API-ключи внешних систем (имя, права, последнее использование) | `api_key` (в БД — префикс и HMAC, не сам ключ) | доступ 1С/ERP клиента к его данным | поручение клиента | до отзыва/истечения; строка — пока клиент существует | внешней системе клиента по его ключу — только в пределах выданных прав |

Минимизация: открытый номер не хранится ни в одной колонке (`tests/invariants/test_i10_no_plaintext_plate.py`),
в логах/метриках/трассах/Sentry — маска или отсутствие (`platform/logging.py` redaction, `test_sentry_and_redaction.py`),
в ответах API операторам — маскированный номер (`plate: str  # маскированный`), полный номер — только по явному
действию с аудитом.

## 2. Локализация (Q6): ПДн не покидают территорию

| Канал | Где данные | Подтверждение |
|---|---|---|
| PostgreSQL (Patroni ×3), PgBouncer | ВМ в ЦОД UZ (Terraform `envs/production`, Proxmox) | INFRA §3, §6 |
| MinIO (кадры, бэкапы, tfstate) | ВМ в ЦОД UZ, репликация во второй MinIO **того же контура** (`mc replicate` — INFRA §4) | INFRA §4 |
| Бэкапы pgBackRest | репозиторий MinIO в контуре, шифрование AES-256-CBC, object-lock | `deploy/postgres/pgbackrest.conf.j2` |
| Логи (Loki), метрики (Prometheus), трассы (Tempo/OTel collector) | namespace `observability` кластера в UZ; в логах нет номеров (I-10), в метриках нет лейблов с ПДн (`docs/backend/metrics-cardinality.md`), спаны с `plate|password|token…` запрещены (`platform/tracing.py`) | OBSERVABILITY §1–3 |
| Sentry | **self-hosted в контуре** (`PARKING_SENTRY_DSN`/`VITE_SENTRY_DSN` указывают на внутренний инстанс), `send_default_pii=False`, тело запроса не отправляется, `before_send` редактирует; фронтенд — `scrub.ts` удаляет `plate*`, токены, cookie | OBSERVABILITY §6; A-46 |
| Платёжные провайдеры (Payme, Click — резиденты UZ) | получают `payment_id`, сумму, `Parking session <uuid>`; номер и кадры — нет | `billing/infrastructure/gateways.py:126,134,245` |
| CI/CD (GitHub Actions) | в GitHub уходят только код и артефакты сборки; тесты в CI используют синтетические данные; раннеры staging/production — в контуре (A-65) | `.github/workflows` |
| Внешние SaaS с ПДн | не используются | CORE Q6 |

Проверка при изменении: любой новый исходящий канал (новый экспортер, вебхук, аналитика) проходит через ревью с
пунктом «ПДн не покидают контур»; NetworkPolicy egress для провайдеров — только 443 к их адресам (Helm
`networkPolicy.providers`), для остального — default deny.

## 3. Права субъекта и процесс запроса на удаление

Цикл (`modules/privacy/domain/request.py`, значения enum `deletion_state` в БД):

```
REQUESTED → IDENTITY_VERIFIED → LEGAL_RETENTION_CHECK → ANONYMIZATION → MEDIA_DELETION → AUDIT → COMPLETED
                      ↘ REJECTED (с причиной, из любого нетерминального состояния)
```

| Шаг | Кто/что | Что происходит | Где |
|---|---|---|---|
| REQUESTED | оператор tenant (`privacy:manage`) по заявлению субъекта; `POST /api/v1/privacy/requests` | номер → хеш (открытый номер не сохраняется), контакт шифруется, `due_at = requested_at + 10 дней` | `service.py::request` |
| IDENTITY_VERIFIED | оператор сверил документ на ТС; `POST …/{id}/verify` c `reason` | I-15: аудит `PRIVACY_IDENTITY_VERIFIED` | `service.py::verify_identity` |
| LEGAL_RETENTION_CHECK | автоматически (`POST …/{id}/process`) | активная сессия → отказ до её закрытия; иначе фиксируются `vehicle_ids` и `retention_note`: строки сессий/платежей **сохраняются** 7 лет (финансовый ретеншен), удаляется идентифицируемость | `service.py::_step_retention_check` |
| ANONYMIZATION | автоматически, одна транзакция, `SECURITY DEFINER app.anonymize_vehicles` | `vehicle.plate_hash → случайный 32-байтный токен` (необратимо, уникально), `plate_encrypted → шифртекст заглушки ANONYMIZED`, то же для всех `anpr_event` и `manual_correction` субъекта; суммы, даты, `session_id`, `payment_id` не меняются; кеши решений доступа по старому хешу инвалидируются | `alembic/sql/0014_up.sql`, `service.py::_step_anonymize` |
| MEDIA_DELETION | автоматически, вне транзакции (I-9) | все версии и delete-marker'ы объектов субъекта в версионируемом бакете MinIO (`S3ObjectStore.delete_all_versions`), `media_object.deleted_at` | `service.py::_step_delete_media` |
| AUDIT | автоматически | `audit_log`: `PRIVACY_ERASURE` с id запроса и счётчиками, без номера | `service.py::_step_audit` |
| COMPLETED | автоматически | сам запрос перестаёт содержать хеш субъекта и контакт | `service.py::_step_complete` |

**Анонимизация вместо удаления**: ЗРУ-547 (ст. 20) и GDPR (art. 17(3)(b)) допускают сохранение данных, необходимых для
исполнения юридической обязанности — финансовые записи о парковке хранятся 7 лет; поэтому строка платежа с суммой и
датой остаётся, а связь с человеком уничтожается: токен не выводится из номера ни при каком ключе (случайные байты,
не HMAC), исходный шифртекст перезаписан. Отчёты по выручке не меняются (тест сравнивает суммы до/после).

**SLA ответа**: 10 календарных дней с даты запроса (`SLA_DAYS`, `deletion_request.due_at`) — срок предоставления
информации субъекту по ЗРУ-547 (ст. 30, «в течение десяти дней»); GDPR (art. 12(3), один месяц) — надмножество.
Точная ссылка на статью и толкование «предоставление информации» vs «уничтожение» подтверждаются юристом — A-67;
внутренний SLA короче обоих. Контроль: `GET /api/v1/privacy/requests?open_only=true` отсортирован по `due_at`;
просроченные — в ежедневном отчёте оператора (RUNBOOK «Запрос субъекта ПДн просрочен»).

Что **не** удаляется и почему: `audit_log` (append-only, 5 лет — содержит `user_id` оператора и `request_id`, не номер);
`anpr_idempotency` (ключ — HMAC от tenant/камеры/хеша/секунды, номер не восстановим; ретеншен 7 дней);
бэкапы **старше** даты удаления (юридический ретеншен 30 дней; при восстановлении из такого бэкапа запросы со
статусом COMPLETED повторно исполняются — RUNBOOK «Восстановление из бэкапа: повтор анонимизаций»).

## 4. Тест необратимости

`tests/privacy/test_erasure.py::test_erasure_request_full_cycle_is_irreversible_and_keeps_finance` (реальные
PostgreSQL и MinIO): сессия с оплаченным обязательством и двумя версиями кадра → полный цикл → проверки:

после удаления** не содержит ни номера, ни старого хеша (= бэкап новее даты удаления чист); выручка и число
сессий/платежей tenant не изменились; аудит без номера. Второй тест: активная сессия блокирует удаление, отказ с причиной.

## 5. Прочие права субъекта

- Доступ/выписка: оператор по документу на ТС выгружает сессии и платежи субъекта (`GET /api/v1/sessions?plate=…`,
  `GET /api/v1/sessions/{id}/payments`) — действие аудируется (`audit_log`, I-15); срок — те же 10 дней.
- Исправление: ручная коррекция номера (`manual_correction`, I-16) с сохранением исходного распознавания.
- Возражение/отзыв согласия: `legal_basis = CONSENT_WITHDRAWN` в том же цикле.
- DPIA-лайт: риски — компрометация DEK tenant (THREAT_MODEL T-11), инсайдер с дампом (T-12) — оба покрыты
  шифрованием и Vault; остаточный риск — кадры до истечения 90 дней.
