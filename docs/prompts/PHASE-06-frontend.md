# PHASE 06 — Frontend

**Предусловие:** gate фазы 5 пройден, `docs/openapi.json` актуален.

---

## 1. Принципы

1. **Типы генерируются из OpenAPI, не пишутся руками.** `openapi-typescript` в CI; расхождение фронта и бэка ловится сборкой, а не пользователем.
2. **Видимость элемента — не граница безопасности.** Скрытая кнопка не защищает эндпоинт. Проверка прав дублируется на фронте только ради UX.
3. **TanStack Query — для серверного состояния, Zustand — только для клиентского.** Дублирование серверных данных в Zustand запрещено: это источник рассинхронизации.
4. **Оператор работает в стрессе.** Экран Live Parking оптимизируется под скорость реакции, а не под красоту: крупные цели нажатия, различимые состояния, никаких модальных подтверждений на частых действиях.

## 3. Live Parking — главный экран

Требования, выведенные из работы оператора:

- Лента въездов и выездов в реальном времени с фото номера.
- Коррекция номера: одно действие, поле ввода уже в фокусе, исходное распознавание остаётся видимым рядом и **не затирается** (I-16). Обязательное поле `reason`.
- Ручное открытие шлагбаума: подтверждение и обязательный `reason`. Это редкое и ответственное действие — здесь подтверждение уместно.
- Приём наличной оплаты: сумма приходит с бэкенда, оператор её не редактирует. Если нужна другая сумма — отдельное действие с `reason` и отдельным разрешением.
- Поиск сессии по номеру (частичному), по времени въезда, по площадке.
- Занятость: вместимость, занято, свободно, процент — крупно.
- Здоровье камер и шлагбаумов: цвет + текст, не только цвет (доступность).
- Осиротевшие сессии и сессии в `MANUAL_REVIEW` — отдельная вкладка со счётчиком.

**Поведение при обрыве WebSocket:** индикатор состояния соединения, автоматическое переподключение с бэкоффом, после восстановления — перезапрос состояния, а не только возобновление потока. Оператор обязан видеть, что данные устарели. Это отдельный тест.

## 4. WebSocket

```
/ws/v1/lots/{lot_id}
```

- Аутентификация при установке соединения (токен в первом сообщении, **не** в query string — он попадёт в логи прокси).
- Проверка доступа к площадке; изоляция tenant обязательна.
- События: `ENTRY`, `EXIT`, `SESSION_CREATED`, `SESSION_CLOSED`, `PAYMENT`, `BARRIER`, `OCCUPANCY`, `CAMERA_STATUS`, `ALERT`.
- Heartbeat в обе стороны, детекция мёртвого соединения.
- Бэкпрешер: при медленном клиенте — дропать промежуточные `OCCUPANCY`, но никогда не дропать `ALERT` и `SESSION_*`. Опиши политику явно.
- Переавторизация при истечении access-токена без разрыва соединения.

## 5. Безопасность

- Токены: access в памяти, refresh — в httpOnly Secure SameSite=Strict cookie. Если выбирается иная схема — ADR с разбором XSS и CSRF.
- Автоматическое обновление токена с дедупликацией параллельных запросов на refresh.
- CSP без `unsafe-inline` и `unsafe-eval`. Если сборка их требует — чини сборку, а не политику.
- Заголовки: `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Секретов в бандле нет. Проверка в CI: `gitleaks` по `dist/`.
- Логаут отзывает refresh-семейство на бэкенде, не только чистит локальное состояние.

---

## 6. Качество

- Ошибки API отображаются по `error.code`, с человеческим текстом и `correlation_id`, который можно скопировать одной кнопкой. Это резко ускоряет поддержку.
- Пустые состояния, состояния загрузки и ошибки спроектированы для каждого экрана. Скелетоны, не спиннер на весь экран.
- Оптимистичные обновления — только там, где откат безвреден. Для платежей и команд шлагбаума — запрещены.
- Доступность: навигация с клавиатуры на операторских экранах, контраст ≥ 4.5:1, состояние не передаётся одним лишь цветом.
- Локализация: русский и узбекский, даты в таймзоне площадки, суммы — форматирование приходит с бэкенда.
